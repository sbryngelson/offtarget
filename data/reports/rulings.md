# Rulings

How the specification is read, and how results are judged, where the text leaves a choice or the measurements
needed one. Each item below is a ruling the bug confirmer applies; `catalog/rulings.yaml` names it by id and quotes
it, and `offload/engine/confirm/registry.py` checks the quotes against this file.

## Device offload only

- scope check is structural (offload/engine/offload_scope.py): any directive outside a target/compute region that is not offload machinery (data environment and motion, declarations for the device, requires, depobj, OpenACC init/set/shutdown/wait, taskwait/taskgroup only with target tasks) and not in a declare target / acc routine procedure is a host construct — every generator (catalog Fortran, C, OpenACC, fuzz) rejects it unless the program declares `scope: host+device` — cost if wrong: a machinery directive misclassified would block a legitimate program (a GenError, never a silent pass).
- fuzz host runs and sequential elision remain references; host_path_failure stays in the data and moves to a labelled appendix ("not offload findings") of each campaign review; the dashboard's host_path_failure rows carry `appendix` — cost if wrong: none.

## Multi-threaded offload

- Ruling: a program whose concurrent target constructs map sections of one
  array that the target regions reference whole is conforming only while
  no construct can find sections from two other constructs present (5.2
  §5.8.3 p.156, "the behavior is unspecified"; 6.0 §7.9.6 p.287
  restriction). The four-thread multi-threaded offload programs
  were not conforming; they now map the arrays whole once (target enter
  data before the host parallel region, target exit data after it; without
  nowait each thread moves its section with target update). The finding
  `multithread-allocatable-section-maps.f90` is kept in its two-thread form,
  which 5.2 defines in every interleaving.
- Ruling: a semantic atom (catalog/<model>/semantic_atoms.yaml) is carried
  by every statement of its program, so a rejection at a directive line is
  the atom's own failure, not a confound.

## Copy mode (HSA_XNACK=0) for the whole catalog, every compiler

- A program that needs zero-copy memory (needs zero_copy: requires unified_shared_memory, self_maps, the self modifier) gets `needs_zero_copy`, not `x1_only`, and its differences are `needs_unified_memory` (supporting a requirement is implementation defined, 5.2 §8.2 p.211); AFAR's refusal of requires unified_address at HSA_XNACK=0 is a class of its own, `requirement_refused` (conforming refusal, not a wrong answer) — cost if wrong: four AFAR C cells would become findings.
- map.iterator (Fortran and C): the program mapped `w(k)` for k = 1, 3, ..., which breaks "the list item instances that would result from different values of the iterator must not have the same containing array" (5.2 §5.8.3 p.156; 6.0 §7.9.6 p.286); it is our bug, fixed to one iterator value (`map(iterator(k = 1:1), to: w(k + 1:n/2))`). Not a rules.yaml entry yet (the scanner has no iterator expansion); the generator test pins the form — cost if wrong: none for the measurement.
- CCE C map(delete) fails in both modes but the program only checks presence in copy mode; classed copy_mode_failure (the catalog cell differs only by mode) with the finding saying it is mode-independent — cost if wrong: a relabel.
- AFAR not enforcing map(present) at HSA_XNACK=1 is a unified_memory_failure (finding), not "the negative probe needs copy mode" as read it: CCE enforces present in both modes on the same hardware and the program has no requires directive — cost if wrong: two AFAR cells per language would move to a no-oracle reading at X1.
- Portable verdict: `neither` now needs an observed failure in some mode (counted rejection, wrong answer, crash, host fallback, a probe that did not terminate, a presence check failing at HSA_XNACK=1); cells with no observable verdict in either mode (unobservable, accepted and ignored, no-oracle and unverified categories, harness errors, rejections not counted) are `not_verifiable` — cost if wrong: counts move between two non-credited verdicts.
- New mode class `x1_oracle_blind` (the X1 cell reads correct only because the check runs in copy mode; a copy-independent check shows the compiler wrong at X1 too): CCE C map.delete (was copy_mode_failure) and AFAR C map.iterator — cost if wrong: a relabel.
- `requirement_refused` is its own verdict (AFAR C unified_address, 4 cells), not `neither`: a conforming refusal of an implementation-defined requirement — cost if wrong: none.
- The AFAR presence reading is confirmed by a second review (5.2 §5.8.3 p.153, §18.8.3 p.389); its x0_only cells (31: 19 Fortran, 12 C; 34 with C map.iterator and transparent) are one bug counted per feature; C reproducer added. The presence summary records host, start and THP.
- Site change on Tuolumne, 2026-10-22 (between 08:50 and 09:46 local): the PE default moved to cce/21.0.4 with a newer cray-mpich, and /opt/cray/pe/lib64/libmpi_gtl_hsa.so.0 (MPI's GPU transport library) now needs libamdhip64.so.7. With cray-mpich loaded, CCE 19 and 20 executables linked it and failed to load under rocm/6.4.3 (exit 127; 7 suite tests).

## Oracle hardening, disputed and provisional expected verdicts

- (Superseded by below: the size reading contradicts the spec's Note.) Static schedule oracle (blocked, schedule(static) and dist_schedule(static) without a chunk size): "approximately equal in size, and at most one chunk is distributed to each thread" (5.2 §11.5.3 p.252; "... to each initial team of the league", §11.6.1 p.256) is read as: each owner's iterations are contiguous, and the nonempty chunks differ in size by at most one; a maintainer may get none (the number of chunks is not fixed). The form required every owner to get m/parts ± 1 and rejected AFAR's conforming 2 × 32 distribution over 4 teams. Cost if wrong: a stricter reading of "approximately" would fail distributions with a short remainder chunk (none observed).
- Bind programs: the loop construct's iterations "may execute in any order, including concurrently" (5.2 §11.7 p.257), so `mine = mine + 1` in every iteration was a data race: the bind(thread), bind(teams)-thread and orphaned bind(parallel|teams) programs (Fortran and C) were nonconforming. Each iteration now writes its own element `hit(i, owner + 1)` (the orphaned forms: a declare target module array, since the C port has no array dummies) and the host sums the columns. bind(parallel), bind(teams) and the teams-nested bind(thread) pass on every compiler as before; bind(thread) in a parallel region still fails on AFAR flang and CCE ftn (finding).
- (Tightened by: trusted needs an executed witness.) Disputed verdicts: a written disposition per program in catalog/expected_triage.yaml. `compiler_wrong` withdraws the listed compilers' runs (all memory modes and both GPUs: the gfx90a and copy-mode runs are runs of the same compilers) as metamorphic and probe witnesses; it needs a finding with a minimal reproducer and a spec citation. All 15 disputed programs are compiler_wrong (schedule 9, bind(thread) 3 after the program fix, defaultmap.character 3); none is implementation_defined. Cost if wrong: a finding that is itself wrong would hide a correct compiler; the reproducers were run 3 times per mode on all four compilers, and the C forms (AMD clang) behave as the spec says.
- Programs that stay provisional (no derivation written): map.self and defaultmap.self (6.0; the value depends on whether the device can access the storage, which differs between the memory modes), num_threads(strict: 4) (6.0; a run may end in error termination if 4 threads cannot be provided, so no single value).
- schedule(static) and dist_schedule(static) without a chunk size are treated alike: both no-oracle `implementation_defined`, checked. Basis: without the clause the schedule is implementation defined (5.2 §11.5 p.248 "If the schedule clause is not specified then the schedule is implementation defined."; §11.6 p.254 for dist_schedule; 5.0 §2.5.1 p.64 def-sched-var, §2.9.4.1 p.122; 6.0 §13.6.3 p.419 auto, §13.7 p.420) and the guaranteed properties are those of the common default distributions, so no single run separates the clause from its absence. The chunk_size forms fix one assignment exactly (round-robin chunks of 4 in owner order) and keep their audited oracles. The dist_schedule basis now quotes the in-section sentence (5.2 §11.6 p.254, 6.0 §13.7 p.420), not Appendix A. For schedule the label rests on that spec text, not on an observed default (the reason text says so since). Cost if wrong: the 20 static cells are not counted as support verdicts although a run shows contiguous chunks; their failures stay visible.
- `derived` (ruling 2): trusted needs, besides two agreeing independent sources, a positive executed witness: a device run that printed the value (any compiler, GPU, memory mode; withdrawn runs excluded), the sequential elision, or a correct_on_device run of the program or its C port in the matrix (any compiler, mode, GPU). Without one the verdict is `derived` (shown in counts, docs and the dashboard's Expected column and filter). compiler_wrong still withdraws the finding's runs from the disagreement; the three reproducers were run on gfx90a too (tioga, 3 runs each: same results), so the withdrawal covers both GPUs (outputs: results/t27a/diag/d1-d3 for MI300A, results/t27a/diag/tioga_d4 for gfx90a; git-ignored). Cost if wrong: a verdict marked derived although some run did show the value elsewhere (under-crediting), never trusted without a run.
- Circular derivations (ruling 3): 4 entries (schedule, schedule.static, dist_schedule, dist_schedule.static; 12 programs) cited this project's "approximately equal" reading; they are rewritten from the spec text alone after the oracle change (the check now tests only spec-guaranteed properties). 5 relaxed induction entries (induction, -plus, -step, -relaxed, -times; 6.0) were removed: under the relaxed modifier the text does not fix the new list item at the start of a chunk, so no value is fixed (they stay provisional). A test forbids derivations that cite a project ruling (any "Task <n>", reports, "this project", "our reading"). Cost if wrong: a derivation that silently restates the oracle would still count; each was re-read against the spec. The linear entries now say they take "the value corresponding to the sequentially last logical iteration" as the value at the end of that iteration.
- Executed witness per memory mode: for a copy-dependent program (offload.engine.expected.copy_independent false) the witness must come from the verdict's memory mode: the copy-mode verdict counts only HSA_XNACK=0 rows (MI300A X0 and gfx90a) and the copy-mode runs, the main verdict only HSA_XNACK=1; copy-independent programs keep any mode (their copy-mode runs are runs of the same program). The 6 iterator programs (5.2/6.0 from-, to-, map-iterator), whose only correct runs are AFAR C at HSA_XNACK=1, are derived in copy mode. Cost if wrong: under-crediting a copy-dependent verdict whose other-mode run would also have shown it.
- Withdrawal in the matrix witness (N2): a withdrawn compiler's rows of the catalog (Fortran) program are no witness; its C port is not withdrawn, because the findings name the Fortran front ends (amdflang, ftn) and the port is compiled by amdclang/craycc. A correct_on_device row prints check=pass (or the required termination), the value a trusted catalog verdict agrees on. Cost if wrong: a C-front-end defect shared with the Fortran one would make the port a false witness; the 5.2/6.0 schedule and bind(thread) witnesses are AFAR C runs with 256 threads (diag d1, d5), so not vacuous.

## The automated bug confirmer (offload/engine/confirm, tools/confirm.py)

- Registry (catalog/rulings.yaml): only rulings of this file a confirmer rule or the legality gate can use; each entry quotes this file and, for a spec reading, the spec sentence on its printed page (checked against the spec text by a test; an item is cited where it starts, so the quote may begin on the next page). Process, mode and environment rulings carry no spec quote. Anything else a rule would need is needs_human — cost if wrong: a reading missing from the registry sends cases to needs_human (more agent work), never to a wrong verdict.
- Ruling (spec reading): under OMP_TARGET_OFFLOAD=mandatory a legal program whose target region reports that it ran on the host (fell_back_to_host: the program's check passed, ran_on_host=1) while another compiler family runs the same program on the device of the same machine and mode is a compiler or runtime failure whatever the computed value: the default device (or the device clause) determines where the region executes (5.2 §13.8 p.284) and with mandatory an unusable device is an error, not a host run (5.2 §21.2.8 p.610). The rule (R19b) needs no expected-value verdict, only the deterministic host report and the other family's device run — cost if wrong: a program whose ran_on_host report is itself wrong on one compiler (a lost copy-back, as CCE 19/20 map.mapper in copy mode) is called compiler_bug for the wrong reason; it is still that compiler's failure.
- Ruling: a rejection the compiler itself calls not implemented (harness reason `not_implemented`, which includes CCE's "Unsupported OpenMP construct") and a construct it accepted and said it ignores (`accepted_ignored`) are `unsupported` (a support gap), not compiler_bug; a diagnostic rejection of a legal program while another compiler family compiles it, an ICE, a link failure on symbols of the compiler's own code and a compile hang are compiler_bug (R10, R11); when every family rejects a program the checkers accept, the rules do not decide (needs_human, R12) — cost if wrong: a vendor's "not implemented" that is really a defect is under-reported; R12 leaves 2,847 batch cells to agents (mostly OpenMP 6.0 forms and OpenACC, where CCE is the only family). **[The R12 part is superseded: maintainer ruling C (every family rejects -> unsupported_everywhere) and its amendment (R12a); the "2,847 batch cells to agents" cost no longer applies.]**
- Ruling A: omp_vv stays untrusted. Its failures remain needs_human (legality unknown); there is no "presumed legal" verdict for corpus tests (registry RUL-OMPVV-UNTRUSTED).
- Ruling B: a Fortran program's hand derivation counts for its C port when the port computes and checks the same value from the same construct; the equivalence is recorded per port as data (catalog/omp/port_equivalence.yaml, checked by a test); a port without an entry stays provisional/derived (registry RUL-PORT-DERIVATION).
- Ruling C: when every compiler family rejects a program and the legality gate passes without the compilers under test, the verdict is `unsupported_everywhere` (not a bug, not needs_human); only when legality is unknown is it escalated (registry RUL-UNSUPPORTED-EVERYWHERE).
- Ruling D: a compiler under test is never a legality checker for its own cases; for other cases a front-end (AFAR flang or clang) rejection counts only if another checker or a ruling agrees (registry RUL-NO-SELF-CHECK). The front-end checkers and their compiler family are data (catalog/machines.yaml frontend_checkers).
- The rule as written (amends R13b): a fuzz program that no compiler runs correctly on the host is `noncompliant` (excluded from findings and tallies: neither a bug nor our_bug), only when the case is a value outcome (wrong answer; never a device crash) and host builds of at least two compiler families ran to a value; every other noncompliant case is needs_human ("excluded by the rule, too little host evidence") — cost if wrong: a real model defect waits for an agent when fewer than two host builds compile.
- Ruling: a registry spec reading whose `applies` names the program (e.g. RUL-DELETE-REFCOUNT for the map-delete programs, RUL-PRESENT-TERMINATION for the map-present probes) is a hand derivation from the spec text: it counts as the `derivation` source next to the program's own oracle, as a header derivation does, and still needs an executed witness — cost if wrong: a spec reading that does not fix the value the check tests would make trust circular; each such entry quotes the sentence that fixes it.
- Ruling (until vendor claims are ingested): a diagnostic rejection of an OpenMP 6.0 form (a program of spec version 6.0 or later) is compiler_bug only if a recorded vendor claim says the toolchain supports that construct at 6.0; without a claim it is `unsupported` with reason "no claim recorded". A catalog 6.0 program counts as a 6.0 form only when the 5.2 program of the same atom is not also rejected (or there is none): a rejection both share is decided by the ordinary rules. Catalog programs and files are treated alike. ICEs stay compiler_bug — cost if wrong: a 6.0 rejection that is a real defect waits for the vendor claims.
- Ruling: runner and collector failures (harness errors: environment, ssh or Tioga failure, a node of the wrong arch, loader errors, no result line) are never evidence: a collector retries once and then reports missing evidence; the evidence store never caches them — cost if wrong: none (a failed cell is run again next time).
- Ruling: flaky means that some repeats of the cell pass and some fail; a failure on every run whose value varies is deterministic (the value spread is reported) — cost if wrong: a race whose value differs on every run is called deterministic; it is still a failure of that compiler.
- Ruling: our_bug from the elision (R13) needs every comparable device cell with a value (the case's mode for a copy-dependent program; withdrawn compilers excluded) to print the elision's value, from at least two families; when some cell prints the program's own claim the case is needs_human with both sides listed (R13a) — cost if wrong: none (contested cases go to an agent).
- Ruling: a dedupe hit needs the same front end, outcome group, a mode and arch the finding lists, and for an ICE the same compiler-source site (file and line, per compiler release: the CCE releases report the same assert at different lines, so a release whose site the finding does not record is a new case, related to the finding); a crash needs the same signal; a run-time match needs two key constructs, or one with the finding's message, or a catalog program the finding names. A hit whose finding has no reproducer of the case's shape (front end, outcome group, mode) is still minimized — cost if wrong: more drafts for agents (related, not duplicate).
- Ruling: the "no fixed value" (R06) and "needs unified memory" (R07) rules apply only to run-time failures (R06: wrong answers only); a rejection, an ICE or a host fallback on those programs goes to the compile-time and host-fallback rules — cost if wrong: none.

## Fuzz at scale (s1, s1x0) through the confirmer

- Later forms without a claim (rule R11c, registry RUL-LATER-FORM-UNCLAIMED): a diagnostic rejection at a form that a later OpenMP version added to an earlier construct or clause is unsupported, not compiler_bug, unless a recorded vendor claim names that form; a general claim of the earlier version (CCE's "full OpenMP 5.0") does not cover it. The forms are data (catalog/later_forms.yaml, each with the spec text that shows when it was added): declare target enter (5.2 §B.2 p.627), thread_limit on target (5.2 §B.3 p.630), a num_teams lower bound (5.1 §2.7 p.100), defaultmap's all category (5.2 §5.8.7 p.162), order on distribute (5.1 §2.11.6.1 p.144). The rejection is attributed to the form by the diagnostic's message or by the directive statement it points at — cost if wrong: a rejection of a later form the vendor would accept as a defect is counted as a support gap (each cell's reason names the form, the citation and the missing claim, and CCE 21's enter claim keeps its enter rejections compiler_bug).
- Generator defect G1 (fuzz-3; found by CCE 19/20/21's ftn-1510 on 11 s1 programs and b5 seed 193): default(none) on a combined construct must also list the variable of an if(<leaf>:) clause whose leaf is nested inside the default's leaf (if(simd: lsimd) on parallel do simd, if(parallel: lpar) on teams distribute parallel do): the clause is applied to its leaf (5.2 §17.2 p.340), so the expression is evaluated inside the region where default(none) applies, and "each variable that is referenced in the construct and does not have a predetermined data-sharing attribute must have its data-sharing attribute explicitly determined" (5.2 §5.4.1 p.109); ruled the same for the C if(parallel: use_dev) programs. offload.engine.fuzz.generator_defects finds it statically; check_rules reports it; the confirmer's legality gate calls such a program illegal (R03, our_bug) whatever its stored check; generator fuzz-4 lists the variable (every other line and the model are fuzz-3's) and the affected seeds were rerun with fuzz-4 (runs s1g4, s1g4x0, b5g4) — cost if wrong: if the clause expression were outside the default's scope, 11 programs' cells would be compiler failures counted as ours (CCE's diagnostics agree with this reading).
- R22b: a run-time failure whose expected value the metamorphic runs dispute (another family's runs of the original and its spec-equivalent rewrites give one value, the program's model another) is needs_human by its own rule with both values in the reason; such cases had fallen through to R99 — cost if wrong: none (needs_human either way).
- A compiler family is no metamorphic witness against the expected value in a case of its own (spot-check fix): a compiler that fails deterministically prints the same wrong value on the spec-equivalent rewrites too, so its stable runs made every such wrong answer "disputed" or "conflict" (needs_human R22) however many other sources agreed; now only other families' rewrites count as the metamorphic source (as a family is never independent evidence), so a wrong answer is compiler_bug (R20) when the model and another family's runs of the original and its rewrites give the same value and that family's device run shows it — cost if wrong: if the other family shared the model's error (a wrong model the other compiler happens to reproduce on every rewrite), a correct compiler would be called wrong; the model, the other family's original and every rewrite would all have to agree on the wrong value.
- A presence or overlap abort ("Variable not found in present table", "Host region ... overlaps present region", the LLVM offload runtime's present-modifier error) is witnessed only by a run that enforces the present check: another family's CCE run, or AFAR at HSA_XNACK=0 (copy mode); AFAR at HSA_XNACK=1 does not enforce present (data/findings/afar-xnack1-present-not-enforced.f90) and the sequential elision has no device data environment (offload.engine.confirm.facts.PRESENCE_ABORT, and the case-level spot check of s1 seed 5153 on CCE 20, an overlap abort decided R20 on an AFAR X1 witness alone). The same restriction applies to decision D8 (seeds 7986 and 9270 leave it; 2232 on CCE 21 joins it through AFAR's copy-mode run) — cost if wrong: presence aborts that are real defects wait for an agent (R22) instead of being called compiler_bug.
- R12 (every family rejects) is not applied to any fuzz program, by design: a fuzz program's rejections by different families concern different constructs; such cells are R12b and go to an agent (D1-D5, D9). The 44 b/c1 fuzz cells this leaves needs_human are outside those decisions — cost if wrong: none (needs_human, never a bug verdict).

## Fixes (2026-10-23)

- Ruling: a compile-time rejection of a feature the vendor documents as unsupported is `unsupported` (documented), not compiler_bug. Rule R11d-documented-unsupported (registry RUL-DOCUMENTED-UNSUPPORTED) runs before R11: the claims data gives three states per (toolchain, primary atom, version, language): claims support (`claimed`: supported, or partial with the form accepted), documents unsupported (an `unsupported` claim and no claim of support), no claim. Only a diagnostic or not-implemented rejection is covered; an ICE, a link failure on the compiler's own symbols and a hang stay compiler_bug. Example: CCE C `requires reverse_offload` (HPE intro_openmp(7): "currently result in compile time errors") — cost if wrong: a vendor document that understates support turns a real rejection defect into a documented gap (still a failure in the support table and a claim match, not a mismatch).
- catalog/cce-nohost-link.f90 is held: its legality rests on RUL-LEGAL-NOHOST-REFERENCE alone (5.2 §13.1 p.275), and both clang front ends under test, CCE's included, reject the C twin — cost if wrong: none (a hold).

## Tooling hardening (2026-10-25)

- Ruling (2026-10-25): a failure that another environment does not reproduce, or reproduces differently, suggests the construct may not be legal, though it is unclear; non-reproduction is a signal for a legality and determinism review, not only flakiness. Every stored failing row goes through the reproduction gate (offload/engine/gate.py: the original build path, another build directory name, another node, a second run), and a row counts as a compiler failure in the reports and the confirmer only when its gate verdict is confirmed; environment, nondeterministic and not_reproduced rows go to the review queue — cost if wrong: a real defect that depends on its environment waits in the review queue instead of being counted.
- Legality needs two independent witnesses that agree: for a program that is not legal or illegal by construction (a finding, a benchmark case, a reproducer), the rules (offload.engine.rules, the restriction checks of offload.engine.prerun and its race rule) and a front end that is not under test (AFAR flang or clang for another family's case; for an AFAR case NVHPC's stored verdict, a witness from another machine) must both accept it for legal and both reject it for illegal; otherwise its legality is unknown (needs_human) — cost if wrong: programs only one witness can judge, AFAR cases without a stored NVHPC verdict among them, wait for a person instead of being decided.
