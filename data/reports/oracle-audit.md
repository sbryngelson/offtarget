# Oracle mutation audit

Generated by `tools/campaigns/oracle_audit.py`; do not edit. Each legal, observable program with an audited evidence level (`construct`, `copy_mode_only`, `probe`) is run as generated (the ORIGINAL) and with its primary atom removed (the MUTANT, `offload.engine.mutate.neutralise`: a directive commented out with its end, a clause deleted from every directive carrying it, a modifier deleted from its clause, a form whose deletion would leave a default that still does the same thing replaced by one without the behaviour (table at the end), conforming fallbacks where a removal would leave an illegal directive; the reporting variables' clauses are never touched; see the module docstring). A check that still passes without the construct is no evidence that the construct works.

Settings: HSA_XNACK=0 (copy mode; programs that need zero-copy memory under HSA_XNACK=1), -O2, one repeat, run timeout 120 s (a timeout is run once more), toolchains afar, cce19, versions 50, 52, 60, version flags as the matrix (run_matrix.for_version: afar 50: -fopenmp-version=50; afar 52: default; afar 60: -fopenmp-version=60; cce19 50: default; cce19 52: default; cce19 60: default); this run: versions 50, 52, 60, merged into the earlier results of the others

Status per program and toolchain: **killed** (original `correct_on_device`, mutant `wrong_answer` or `fell_back_to_host`), **survived** (both `correct_on_device`), **inconclusive** (original not `correct_on_device`, mutant rejected by the compiler, a mutant timeout, the compiler saying it ignored something, or a harness error), **not_applicable** (no mutation, see below). Per atom: **valid** (killed on at least one toolchain), **weak** (survived on every toolchain where it was conclusive), **unknown** (no conclusive result).

Kill kinds: `check_fail` (the run completed and the check failed), `fell_back_to_host` (the run reported ran_on_host=1), `crash` (signal, non-zero exit, no RESULT line). Only `check_fail` shows that the check itself depends on the construct; atoms valid only through the other kinds are marked.

Programs that need zero-copy memory run under HSA_XNACK=1 (marked `xnack=1`): there host and device memory coincide, so a `survived` there proves nothing about data motion.
