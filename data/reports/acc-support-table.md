## How to read a cell

- **correct on device**: the check passed and the region ran on the device; the evidence column says how strong that is: `construct` (the check depends on the construct), `probe` (a negative probe: the program names an absent item with the present modifier, so the run must end in the runtime's error termination; the cell reads 'error termination as required (negative probe)', and a run that went on reads 'no error termination (negative probe)'; or a compile-output probe: an error directive with at(compilation) whose message must appear as a warning, or whose fatal severity must stop the compile), `copy_mode_only` (the check separates the construct from a no-op only at HSA_XNACK=0; the headline cell says so and carries ◊: the real check is the copy-mode column, or the cell says 'copy-mode check not run'); the categories below have no separating oracle and are never credited as supported.
- **accepted; conforms vacuously** (`hint_only`): the spec lets an implementation ignore the form (a hint, an assertion the program makes, or a bound one-at-a-time execution meets); **implementation-defined** (`implementation_defined`): the spec leaves the behaviour to the implementation; **equivalent to the default (no separable effect)** (`equivalent_default`): by the spec the form is the behaviour without it. The cell reads so when the program compiled and ran cleanly; the spec sentence is in the citation column and in the section 'Atoms without a separating oracle'. Where the program checks what the form requires (e.g. the number of teams within the bounds) a failure reads as a wrong answer.
- **accepted (its oracle is the illegal variant)** (`legality`): the atom's only effect is a compile-time restriction (default(none)); its oracle is the illegal variant in the illegal-variants table.
- **accepted; unverified (an oracle is possible but missing)** (`unverified`): the spec fixes the behaviour and a deterministic check is possible, but the program does not have it (the audit disposition says why).
- **wrong answer (confirmed)**: the atom's oracle is audited valid (a mutant without the construct is killed on at least one toolchain). **wrong answer (oracle unaudited)** / **oracle unaudited**: measured outcome, but no toolchain passes the original program, so the oracle is unaudited; not a confirmed failure.
- **crash: SIGABRT, HSA_XNACK=1 only**: the program aborts in that memory mode only (shown instead of a plain wrong answer).
- **fails in copy mode: needs zero-copy memory**: the program needs HSA_XNACK=1; failing at HSA_XNACK=0 is expected and is not a feature result.
- **The OpenACC audit runs on CCE 19 only**: for these atoms CCE 19 fails the original while another toolchain passes it in the matrix, so 'oracle unaudited' does not mean that no compiler runs the program: `clause.default` (3.4), `clause.default.present` (3.4), `clause.firstprivate` (3.4), `clause.firstprivate.implicit_scalar` (3.4), `directive.declare` (3.4), `directive.loop` (3.4).
- Illegal variants: **rejected** / **not rejected** only; acceptance of an illegal program is a neutral observation, never a wrong answer.

## Vendor claims versus measurements

All claims are **provisional** and cited in [claims.yaml](../../catalog/vendor_claims_generic.yaml). A claim covers an atom by name or pattern; a release-level (general) claim applies only where no specific claim for that toolchain covers the atom. Comparison rules: `supported` is contradicted by rejected, ignored, fell back, wrong answer or crash; `unsupported` by correct on device (or, for a compile-error claim, by anything but rejection); `partial` only when the vendor says the form is accepted and it is rejected. Cells that cannot separate the construct (no oracle: hint only, implementation-defined, equivalent default; legality; unverified; unobservable) never contradict a claim, except that a crash of such an atom does (a crash needs no oracle), and they never count as support; zero-copy programs in copy mode and illegal variants are not compared. Both memory modes are compared where both ran.
