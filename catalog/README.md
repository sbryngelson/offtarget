# catalog/

The configuration the engine reads. It records what the specifications require, what the vendors claim, which compilers and machines are measured, and the decisions taken on the results. Code never writes a hand-written file here. Each generated file is written by one command, and `python3 -I tools/regenerate.py --check` checks that it is current. [../docs/tooling/regenerate.md](../docs/tooling/regenerate.md) explains regeneration and [../docs/how-it-works.md](../docs/how-it-works.md) shows how the files fit together. [../docs/tooling/toolchains.md](../docs/tooling/toolchains.md) lists the toolchains and machines.

| role | files | origin |
|---|---|---|
| specification slices | [omp/](omp/README.md), [acc/](acc/README.md): rules, clauses, claims, semantic atoms, out-of-scope atoms; `later_forms.yaml`, `dataenv_rules.yaml` | hand-written; each `skeleton.yaml` is generated from `data/index/seed/` |
| toolchains and machines | `toolchains.yaml`, `machines.yaml`, `canaries.yaml`, `mode_differences.yaml`, `toolchain_names_allowlist.yaml`, `local.example.yaml` | hand-written; `local.example.yaml` is a template for the per-user `local.yaml` (git-ignored), which adds install paths and ssh access; `site/static/toolchains.js` and `docs/tooling/toolchains.md` are generated from `toolchains.yaml` and `machines.yaml` |
| vendor claims | `vendor_claims.yaml`, `vendor_claims_generic.yaml` | `vendor_claims.yaml` is hand-written; `vendor_claims_generic.yaml` is generated by `tools/derive/claims.py ingest` |
| confirmer rules and decisions | `confirm_rules.yaml`, `rulings.yaml`, `expected_triage.yaml`, `triage_27b.yaml`, `triage_28.yaml`, `upstream_status.yaml`, `unlinked_bugs.yaml`, `gate_queue.yaml`, `citation_allowlist.yaml` | hand-written or recorded decisions; `gate_queue.yaml` is generated by `data/evidence/gate_probe/build_queue.py` |
| legality witnesses | `legality_witness.yaml` | generated by `tools/confirm.py witness` |
| fuzz and stress | `fuzz_campaigns.yaml`, `fuzz_profile.json`, `parity_fuzz_sample.json` | `fuzz_campaigns.yaml` is hand-written; the others are generated by the fuzz and parity tools |
| benchmark bookkeeping | `sealed_spent.yaml`, `*_holdout_excluded.yaml`, `harvest_*.yaml`, `harvest2_*.yaml`, `harvest_spec_names.txt` | hand-written, except `harvest_spec_names.txt`, which `tools/campaigns/harvest.py spec-names` generates |
| data-environment campaign | `dataenv_pilot.yaml` | hand-written: the 40 rules of the campaign's pilot trial, each marked near or away from a finding (`tools/dataenv/dataenv.py`) |
| ratchets | `findings_claims_baseline.yaml`, `standing_rules_baseline.yaml` | violations that existed when a check was added; the check fails on any violation not listed |

`sealed_spent.yaml` lists the sealed sets that have already been scored. [../data/bench/README.md](../data/bench/README.md) describes the sets.
