### How each derivation was checked

Each entry of catalog/omp/derivations.yaml was written from the program as
generated (src dump of all 1,529 programs) and the cited text (pdftotext of
spec/openmp, page-aware search), not from the generator's check code; the
cites carry the page of the program's own version. tests/engine/test_gen.py checks
that every entry reaches its program's header with the version's citations
and that the audited body does not change.

## Oracle hardening (brief item 6)

- Detector (offload.engine.mutate.uninit_from_items), fixed per the
  Host code of the main program only; lines inside target and
  OpenACC compute regions, modules and internal procedures do not initialize;
  declaration/DATA initializers, calls receiving the item, memset, component
  and element writes do; a C pointer section needs element writes; the
  statement after a standalone C directive is check code. Tests:
  tests/engine/test_generators.py (each case of the review, both directions).
- Effect on the catalog list: 140 -> 132. Removed (over-listed): the 10 C
  distribute/distribute_parallel_for(_simd)/distribute_simd/loop programs
  (5.2, 6.0), whose `cnt` is set in a nested host loop. Added (missed): C
  omp52/omp60 defaultmap-pointer, item `pw` (checked after `target exit
  data`). The review's 5 candidates (item `b`) are host-initialized by the
  frame. No catalog program relies on a prior target region or a component
  to initialize an item.
- Hardening (offload/engine/gen_templates.py, offload/engine/c_gen.py): each item starts
  at `SENTINEL` = -1 (C `pw = NULL`): teams/num_teams/thread_limit/device/
  if-directive_name/num_threads/dist_schedule (`team_param`), parallel_do(_simd)
  (`nref`, `nthr`), schedule (`tid`, `nthr`), schedule-monotonic (`tid`, `ord`),
  collapse (`tid`, `nthr`), ordered (`seq`). Every check rejects -1; the
  schedule and dist_schedule checks also test `nthr >= 1` / `nt >= 1` and that
  every owner number is in range (a lost count would otherwise only empty a
  loop). 132 legal programs and 70 illegal variants derived from them change
  (only by those lines); the list is now empty (tests keep it so).
- Reruns: every changed program on afar, cce19, cce20, cce21 at HSA_XNACK=1
  and 0 (tuolumne, THP always, tools/run_oracle_hardening_rerun.sh) and on the gfx90a twins
  (a Tioga node, every GCD visible, tools/jobs/run_tioga_oracle_hardening_rerun.sh); oracle audits
  (--merge) and map audits (AFAR, CCE 19; both modes on MI300A, X0 on gfx90a)
  of the changed programs; expected-behaviour runs of those in the set.
- Results of the originals: unchanged. Fortran 1,512 cells (1,008 MI300A, 504
  gfx90a), C 1,236 (824, 412): every cell has the same outcome except 18
  Fortran and 24 C dist_schedule(static) cells that the corrected oracle turned
  from wrong_answer to correct_on_device (AFAR Fortran in every mode and GPU;
  CCE C at HSA_XNACK=0 and on gfx90a).
- Map audit: gfx90a survivors 844 -> 824, oracle_weakness_uninit 42 -> 0 (20
  mutants now killed; 22 drop_map mutants of the C distribute/loop and C
  ordered programs move the same data through the implicit tofrom map of the
  arrays and are `covered`); agreement with MI300A X0 4,101 of 4,101 (the 2
  AFAR parallel_do_simd drop_map differences are gone).

## Program and oracle changes found by the triage

- loop bind programs (bind.thread, bind with bind(thread) in teams, orphaned
  bind.parallel and bind.teams; Fortran and C): nonconforming before (a
  counter shared by iterations that may run concurrently, 5.2 §11.7 p.257);
  each iteration now writes its own element. Outcomes unchanged.
- blocked oracle (schedule and dist_schedule without a chunk size), as
  fixed: every iteration ran on a maintainer 0.. parts - 1 and
  each owner's iterations are one contiguous run; no chunk size is checked
  (the spec's Note calls ceil(n/p) chunks and q / q - 1 splits alike
  compliant). The first form ("nonempty chunks differ by at most one") was
  reversed.
- schedule(static) and dist_schedule(static) without a chunk size (Fortran
  5.0/5.2/6.0, C 5.2/6.0): no-oracle implementation_defined, checked, by one
  reading (without the clause the schedule is implementation defined and may
  be such a split; bases `schedule_default`, `dist_schedule_default`). Their
  cells read implementation-defined, not a support verdict; failures (the
  CCE C crash, the Fortran cyclic distribution) are still shown. Fix
  reran them (and the bind programs, now starting nthr at the sentinel) on
  every compiler, both modes and gfx90a: no outcome changed against the first
  Run.

## Claim mismatches and omp_vv flags through the confirmer

Method (docs/tooling/confirm.md "Vendor claims, mismatches and omp_vv flags"): every
vendor statement of the documents listed in catalog/vendor_claims.yaml was
ingested into the generic claims format (catalog/vendor_claims_generic.yaml,
`tools/derive/claims.py ingest`; each quote checked against the snapshot of each
release in data/index/claims): 1,603 atom-level claims from 187 (document, release, statement) quotes (HPE 1,184 for CCE 19/20/21
from intro_openmp(7), intro_openacc(7), the release notes and the OLCF
Frontier guide; AMD 419 for AFAR from the ROCm page, the AMD-hosted Clang 20
table, and the amdclang and amdflang tables and Todo tests at the AFAR
commit). The support tables compute the mismatches (Fortran 141, C 134,
OpenACC 12: 287; one per claim, atom, version and compiler, gfx90a twin cells
included; 117 before, cce19 and afar only). `tools/confirm.py triage` turns
every mismatch and each of the 118 omp_vv flags into cases, decides them
offline and computes each item's disposition; the needs_human items (95
mismatches, 56 flags at the first pass) were decided by an agent in
catalog/triage_27b.yaml with spec text and probes (data/evidence/triage_probe,
results/t27b/probes.jsonl). Rulings: data/reports/rulings.md.

Fixed on the way: the C (and Fortran) if(parallel: use_dev) programs were
nonconforming (use_dev unlisted under default(none); rerun on every compiler,
both modes and gfx90a: the C ports now compile and run correctly
everywhere, the Fortran results are unchanged); confounds now apply to CCE
20/21 and the gfx90a twins (report.family shadowing); omp_vv rows stored as
"compile_failed" are read from their output (spot check). New findings:
`clang-c-declare-target-to-omp52.c`, `clang-c-map-iterator-omp51.c`,
`defaultmap-none-loop-variable.f90`, `cce21-linear-modifier-default-none.f90`
(data/findings/README.md). Suspected suite test bug: docs/upstream.md
(draft, not filed).
